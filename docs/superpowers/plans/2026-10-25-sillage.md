# Sillage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **Repository override:** `AGENTS.md` interdit les sous-agents sans demande explicite. Utiliser `executing-plans` dans la session courante et effectuer la revue soi-même. Les étapes de tests restent conditionnelles à une demande explicite.

**Goal:** Livrer un client YouTube Music sans WebView, réactif, visuellement soigné et économe en ressources.

**Architecture:** Un exécutable Rust possède une UI Slint et des workers bornés pour le service, les pochettes et l'audio. Les événements et générations relient ces composants sans polling. Les données de Sillage sont indépendantes d'UltraMusic.

**Tech Stack:** Rust, Slint/Winit/FemtoVG, Symphonia, rodio, ureq, serde/serde_json, windows-rs ; versions stables épinglées au squelette.

**Spec:** [Design du projet](../specs/2026-10-25-sillage-design.md).

## Global Constraints

- Cible initiale : Windows 11 x64.
- Stack : Rust + Slint ; Symphonia + rodio ; API Windows via windows-rs.
- Aucun navigateur embarqué ni WebView dans l'interface ou la lecture audio.
- Aucun sous-agent sans demande explicite de l'utilisateur.
- Aucun test unitaire ou fonctionnel sans demande explicite de l'utilisateur.
- Aucun lancement du lecteur ni contrôle du bureau sans réautorisation explicite.
- Aucun changement des données, identifiants ou fichiers d'UltraMusic.
- Aucun secret ni URL de flux signée dans Git, les logs ou les rapports.
- Aucun contournement de DRM ni promesse de qualité ou de fonctionnalité non vérifiée.

Tous les budgets du design s'appliquent aux tâches concernées. Aucun test ni
programme n'est lancé par la seule présence de cette roadmap. Après approbation
de l'implémentation, `cargo fmt --check`, `cargo clippy --locked --all-targets -- -D warnings`
et `cargo build --locked --release` sont les contrôles statiques proposés.
Clippy peut compiler les cibles de tests ; il ne les exécute pas.
Si les tests sont autorisés, préparer les cas nommés de chaque tâche avant son
implémentation, observer l'échec, puis vérifier la réussite après le changement.

## Review Focus

1. Réponses périmées après changement de recherche ou de piste : ignorer leur génération, tâches 2 et 4.
2. Flux expiré, réponse 429 ou réseau coupé pendant lecture : erreur récupérable, jamais boucle de retries, tâches 2 et 4.
3. Compte expiré ou déconnexion pendant une requête : aucune donnée personnelle réappliquée, tâche 7.
4. Disque plein ou reprise invalide : garder l'ancien état et rester utilisable, tâche 6.
5. Longues listes, DPI élevé et changement de périphérique audio : interface accessible et état cohérent, tâches 5 et 9.

## Ordre et jalons

`0 Faisabilité → 1 Lecteur local → 2 Recherche → 3 Navigation → 4 Streaming → 5 File → 6 Reprise → 7 Compte → 8 Windows → 9 Finition → 10 Mesures → 11 Distribution → 12 V1`.

M0 = tâche 0 ; M1 = tâche 1 ; M2 = tâches 2–6 et 8 ; M3 = tâche 7 ;
M4 = tâches 9–11 ; V1 = tâche 12. Une alpha M2 peut être livrée sans compte
si ses limites sont explicites. M3 ne peut pas être simulé par une bibliothèque locale.

Ne pas lancer tous les sous-projets simultanément. Le risque de service est traité
avant l'investissement dans la finition. Pas d'échéance inventée : estimer les
jalons restants après M0 et la mesure de l'effort réel de M1.

## Structure et contrats communs

Les chemins ci-dessous sont relatifs à la racine Sillage. Tous les fichiers
applicatifs sont à créer ; consulter `docs/ARCHITECTURE.md` pour leurs propriétaires.
Les fonctions ci-dessous fixent les frontières, pas des abstractions de plugins.

Dans `src/model.rs`, définir au fil des tâches :

- `RequestId(u64)` : génération de requête ; ne jamais réutiliser une valeur pendant le processus.
- `Track { id: String, title: String, artists: Vec<String>, duration_ms: Option<u64>, artwork_url: Option<String> }`.
- `SearchPage { tracks: Vec<Track>, continuation: Option<String> }`.
- `BrowseTarget` : variantes `Album(String)`, `Artist(String)`, `Playlist(String)`.
- `BrowsePage { title: String, tracks: Vec<Track>, continuation: Option<String> }`.
- `ServiceOperation` : `Search(String, Option<String>)`, `Browse(BrowseTarget, Option<String>)`, puis `Home` et `Library` en tâche 7.
- `ServiceReply` : `Search(SearchPage)`, `Browse(BrowsePage)` ; les réponses compte utilisent `BrowsePage`.
- `ServiceError` : `Network`, `RateLimited`, `Unauthorized`, `Unavailable`, `Unsupported`, `InvalidResponse`, `Cancelled` ; conserver une cause interne expurgée.

Dans les modules propriétaires : `PlaybackCommand`, `PlaybackEvent`, `PlaybackError`
appartiennent à `playback` ; `Queue` à `queue` ; `ResumeState`, `Settings` et
`StorageError` à `storage`. Ne pas faire de `model.rs` le conteneur de tous les détails.

Les canaux de commandes et d'événements ont une capacité initiale de 32 éléments.
Une UI n'attend jamais sur un envoi bloquant. Coalescer la progression et conserver
les changements d'état ; un canal plein produit une erreur récupérable ou un réveil
déjà programmé. Aucun blocage du callback audio par réseau, disque ou UI.

Chaque tâche finit par une revue du diff, la mise à jour de `docs/STATUS.md` et
un commit limité à ses fichiers, après les contrôles autorisés. Aucun push forcé.
